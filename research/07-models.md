# 07. Какие LLM выбирать

> Связь со SPEC: раздел 8 (LLM и бюджет), 6 (лимит попыток), 11 (вторая фаза и локальные модели).

## Вопрос

Какие модели подходят для каждой роли в пайплайне? Что важно знать про API Claude, сколько это будет стоить, и годятся ли локальные модели?

## Короткий ответ

- **Уровень моделей:** лучшие облачные модели 2026 года решают задачи международного конкурса для школьников **с рисунками** на 72–95%, а текстовые — ещё лучше. Для текстовой части решение задачи не узкое место. Узкие места — генерация и проверка однозначности.
- **В текущем SPEC есть техническая ошибка.** Claude Sonnet 5 и Opus 5 **не принимают `temperature`** — запрос вернёт ошибку 400. Детерминированность Аналитика задаётся не температурой, а уровнем «усилия» (`effort`).
- **Structured outputs** (`output_config.format`) гарантируют, что ответ соответствует JSON-схеме. Условие «JSON валиден» из SPEC 6 выполняется самим API.
- **Стоимость.** По грубой оценке, одна попытка генерации стоит порядка **$0.10–0.20**, так что цель «< $0.10 за принятую задачу» при Генераторе на Opus 5 скорее всего не выполняется без кэширования и тюнинга `effort`.
- **Локальные модели 2026 года** сильны в *решении* (gpt-oss-20b в 16 ГБ, небольшие Qwen), то есть роли решателя и проверяющего реалистичны локально. *Генерация* нестандартных задач — самая трудная роль для маленьких моделей.

## Что известно

### Claude API: модели и цены

Данные из актуальной документации Anthropic, снимок от 24.06.2026:

| Модель | ID | Контекст | Вход $/1M | Выход $/1M |
|---|---|---|---|---|
| Claude Opus 5 | `claude-opus-5` | 1M | $5 | $25 |
| Claude Sonnet 5 | `claude-sonnet-5` | 1M | $2 | $10 |
| Claude Haiku 4.5 | `claude-haiku-4-5` | 200K | $1 | $5 |

Важные для нас свойства API:

- **`temperature`, `top_p`, `top_k` удалены** на Opus 5 и Sonnet 5 — запрос с ними вернёт ошибку 400. На Haiku 4.5 они ещё работают.
- **Размышление (`thinking`)** на Opus 5 включено по умолчанию (адаптивное), глубина регулируется `output_config.effort` (`low` … `max`). У Haiku 4.5 — старый режим с `budget_tokens`.
- **Structured outputs:** `output_config.format` с JSON-схемой, в SDK — `client.messages.parse()` с проверкой ответа.
- **Нет «префилла»** — нельзя начать ответ модели за неё на Opus 5 и Sonnet 5.
- **Prompt caching:** чтение кэша ~0,1× цены входа, запись 1,25× (кэш на 5 минут). Минимальный кэшируемый префикс — 512 токенов на Opus 5 и 4096 на Haiku 4.5. Few-shot примеры и системный промпт Генератора — идеальный кэшируемый префикс.
- **Batch API:** −50% ко всем токенам, асинхронно. Подходит для прогонов ради датасета, не подходит для интерактивного `--answer`.
- **Исполнение кода** — серверный инструмент Anthropic (`code_execution`). Альтернатива своей песочнице для программной проверки (см. [05](05-verification.md)).
- ID Haiku в документации — `claude-haiku-4-5`. В SPEC записан датированный вариант `claude-haiku-4-5-20251001`, стоит сверить при запуске.

### Где модели 2026 года на задачах конкурса для школьников

- MathArena, задачи конкурса 2025 года (как изображения): GPT-5.5 — 94,9%, GPT-5.4 — 92,5%, Gemini 3.1 Pro Preview — 89,4%, Claude Opus 4.6 — 72,3%. Более новые Claude (Opus 4.7/4.8/5) в сводке не фигурировали.

Замечание: бенчмарки меряют **решение**, а нам нужна **генерация**. Для неё важнее следование инструкциям, креативность и формат. Отдельная работа (2025) показывает, что рассуждающие модели могут *хуже следовать инструкциям* по мере роста рассуждений (*Scaling Reasoning, Losing Control*).

### Локальные модели

- **gpt-oss-20b** (OpenAI, август 2025, открытые веса): MoE, 21B параметров, из них 3,6B активных; работает в **16 ГБ** памяти. По model card — 98,7% на AIME 2025 с инструментами. Очень сильный решатель для своего размера.
- **Qwen3** (2025) и **Qwen 3.5 small** (март 2026, 0,8–9B): по вторичным источникам 9B работает на ноутбуке с 16 ГБ и сильна в математике и структурированном выводе. Цифры из блогов не проверял.
- **DeepSeek-R1-distill 32B** — рассуждения, близкие к полной R1, на одной видеокарте 24 ГБ (по обзорам).
- **Опыт Eedi на Kaggle:** победители дообучили Qwen2.5 7–32B для узкой задачи «ошибка → заблуждение» — локальные модели после дообучения хорошо справляются с узкими ролями (см. [04](04-distractors-misconceptions.md)).

## Оценка стоимости нашего пайплайна

**Грубая оценка, допущения мои.** Проверять по `requests` / `attempts` после первых 10–20 запусков.

| Шаг | Модель | Токены вход / выход (с размышлением) | Стоимость |
|---|---|---|---|
| Методист | Haiku 4.5 | ~3K / ~1K | ~$0.008 |
| Генератор | Opus 5 | ~6K / ~3–5K | ~$0.10–0.16 |
| Аналитик | Sonnet 5 | ~1K / ~2–3K | ~$0.02–0.03 |
| Скептик | Sonnet 5 | ~1,5K / ~2–3K | ~$0.02–0.03 |
| **Одна попытка** | | | **~$0.15–0.23** |

- Главная статья расходов — **выход Генератора на Opus 5**: размышления тарифицируются как выход.
- С кэшированием few-shot префикса входная часть Генератора дешевеет в ~10 раз, но она и так небольшая. Решающие рычаги — `effort` у Генератора и выбор модели.
- Прогоны ради датасета через Batch API — вдвое дешевле.
- При цели «< $0.10 за принятую задачу» и ~1,5 попытки в среднем без изменений цель, скорее всего, не выполнится. Варианты:
  - снизить `effort` у Генератора;
  - поставить Генератор на Sonnet 5 и сравнить качество;
  - честно пересмотреть цель.

## Как решали другие

- **Каскад моделей:** сильная для генерации, дешёвая для рутины — как в SPEC.
- **Разные семейства для проверки** (см. [05](05-verification.md)).
- **Локальные модели после дообучения для узких ролей** (Eedi).

## Проблемы и ограничения

- Цены и возможности моделей быстро меняются, снимок документации — июнь 2026.
- Цифры по локальным моделям частично из блогов.
- Кэши у разных моделей раздельные: при каскаде из четырёх моделей кэш не переиспользуется между шагами.

## Выводы для прототипа

1. **Исправить SPEC 8:** убрать `temperature: 0` у Аналитика (Sonnet 5), вместо этого задать `effort`. На Opus 5 и Sonnet 5 температуры нет вообще.
2. **Использовать structured outputs** для всех агентов — это снимает класс ошибок «невалидный JSON».
3. **Кэшировать системный промпт и few-shot Генератора.** Прогоны для датасета запускать через Batch API.
4. **Сверить ID Haiku** (`claude-haiku-4-5`).
5. **Бюджет:** реалистичная цена попытки ~$0.15–0.23. Цель «< $0.10» пересмотреть или сразу проверить Генератор на Sonnet 5 и с низким `effort` на Opus 5.
6. **Вторая фаза:** первым переводить на локальные модели решателя и проверяющего — у gpt-oss-20b и небольших Qwen сильная математика. Генератор — последним.
