# 04. Варианты-ловушки и типичные ошибки учеников

> Связь со SPEC: 5.2 (`distractors`), 4.1 (`trap_hit`, `cognitive_profile`), 5.1 (`traps_to_use`).

## Вопрос

Насколько хорошо LLM придумывают неверные варианты ответа, которые отражают реальные ошибки детей? И как связать выбранный неверный вариант с конкретной ошибкой ученика?

## Короткий ответ

- LLM умеют придумывать **математически правдоподобные** неверные ответы, но **плохо предсказывают, какие ошибки дети делают на самом деле**. На данных Eedi дистракторы от LLM оценены на 2,68 из 5 по правдоподобию, а составленные людьми — на 3,72.
- Лучше всего работает подсказка **похожими задачами с уже известными ловушками** (kNN-примеры). Она обошла и цепочку рассуждений, и дообучение.
- Связывание «неверный ответ → ошибка» — отдельная решаемая задача. Победители соревнования Eedi на Kaggle решали её дообученными Qwen 7–32B и рассуждениями, которые сгенерировал Claude.
- Главный ресурс здесь — **реальные ответы детей**, а не модель.

## Что известно

### Eedi, NAACL 2024 Findings

- Датасет: 1,4 тыс. реальных тестовых задач Eedi для детей 10–13 лет (арифметика, дроби, округление) с распределением ответов учеников. Известно, какие неверные варианты дети реально выбирают.
- Сравнили пять подходов:

  | Метод | Exact match | Partial match | Proportional |
  |---|---|---|---|
  | kNN — 3 похожих примера в промпте | 10,95% | 73,85% | 38,52% |
  | Chain-of-Thought (GPT-4) | 4,24% | 65,02% | 30,39% |
  | Правила — 44 объяснения ошибок | 4,95% | 57,95% | 27,21% |
  | Дообучение ChatGPT | 2,83% | 57,95% | 25,32% |
  | Сэмплинг ответов решателя | 0,00% | 10,25% | 3,65% |

- Вывод авторов: «хотя LLM могут генерировать математически корректные дистракторы, они хуже предсказывают типичные ошибки и заблуждения реальных учеников». Похожие задачи работают, потому что у них похожие ошибки.
- Люди оценили правдоподобие дистракторов от LLM в 2,68 из 5, а от людей — в 3,72.

### Kaggle: Eedi — Mining Misconceptions in Mathematics (2024)

- Задача: для каждого неверного варианта найти заблуждение, которое к нему приводит. Метрика MAP@25, призовой фонд $55 тыс.
- **1-е место (команда MTH 101):**
  - дообучены три модели Qwen2.5 (Math-7B, 14B, 32B) как «рассуждатели»;
  - сначала Claude 3.5 Sonnet сгенерировал рассуждения «почему ученик выбрал этот неверный ответ»; ему давали условие, верный и неверный ответ и заблуждение;
  - пайплайн «найти кандидатов → переранжировать».
- По итогам Eedi: модели учили на «10 тыс. синтетических и 1,8 тыс. реальных примеров». Заблуждения следуют предсказуемым паттернам, и узкие решения под предметную область работают лучше общих NLP-подходов.

## Как решали другие

1. **Каталог заблуждений.** У Eedi — таксономия типичных ошибок, к которой привязаны дистракторы.
2. **Похожие задачи как подсказка** (kNN) вместо общих инструкций.
3. **Реальные ответы учеников** как истина: какие варианты действительно выбирают.
4. **Синтетика плюс немного реальных данных** для дообучения узкого классификатора.

## Проблемы и ограничения

- Данные Eedi — это школьная программа 10–13 лет (дроби, округление), а не олимпиадные задачи 1–4 классов. Типичные ловушки «Кенгуру» (±1, пропуск случая, двойной счёт, частица «не») похожи по духу, но отдельного каталога для них я не нашёл.
- Без штрафа за ошибку дети часто **угадывают**, поэтому часть `trap_hit` будет шумом (см. [02](02-kangaroo-domain.md)).
- При пяти вариантах дистракторов четыре. Придумать четыре *разных* правдоподобных ошибки для задачи 1–2 класса трудно, и часть вариантов неизбежно будет «пустой».

## Выводы для прототипа

1. **Сделать закрытый каталог ловушек `traps.json`** — как `skills.json` для навыков. В `distractors`, `traps_to_use` и `trap_hit` использовать id ловушки, а не свободный текст. Иначе нельзя посчитать, какие ловушки ученик ловит чаще: «missed one case» и «forgot a case» станут разными ошибками. Стартовый список может составить автор по опыту «Кенгуру»: ±1 в промежутках, пропуск случая при переборе, двойной счёт, игнорирование «не», ответ на другой вопрос, остановка на промежуточном результате и т. д.
2. **Размечать ловушки в эталонных задачах.** Eedi показал: лучшие дистракторы дают похожие задачи с известными ловушками. Эталоны в `examples/kangaroo.json` стоит хранить с полем «какой вариант — какая ловушка».
3. **Копить реальные ответы детей.** В `student_tasks` уже есть `chosen_option`. По ним со временем видно, какие дистракторы дети реально выбирают, а какие никто не выбирает. Это главный путь улучшения ловушек. Первые данные даст ребёнок автора.
4. **Не делать далеко идущих выводов по одному `trap_hit`:** это может быть угадывание. Обновлять `cognitive_profile` только по повторяющимся ловушкам.
5. **Правдоподобие дистракторов** добавить в ручную проверку качества (SPEC 9).
